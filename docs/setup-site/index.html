Your blog needs a home you control.

Shareblog isn't a hosted service — there's no shareblog.com account to sign up for. This page walks through giving your posts a home of their own: a server, a domain, and about twenty minutes.

The idea

Yours the way a domain is yours

Shareblog turns a share-sheet tap into a real post — a thought, a photo, a book, a song, an article, a quote — published on a site that belongs to you, not to a platform. It's Fediverse-native too: anyone on Mastodon or elsewhere in the Fediverse can follow your site directly.

That independence is a deliberate trade. It takes a bit of setup up front, but nobody can shut your site down, put it behind a paywall, or change the rules on you later. It's yours the way a website or an email address is yours — not the way a social account is.

What you need

Before you start

  • A place to run a small always-on process — a few dollars a month covers it comfortably; see hosting options below.
  • A domain name you control — so you can add DNS records for it.
  • A terminal — setup is a handful of copy-pasted commands over SSH, no ops experience required.
  • About 15–20 minutes.

Where to host

Pick a home for it

Shareblog is one small Node process backed by a single SQLite file — no database server, no container orchestration, nothing exotic. It runs comfortably on the cheapest tier of almost any host.

Setup steps

The short version

This is the shape of it — the linked guides above have the exact commands for your host.

  1. Get the code and install

    git clone the repo onto your server, then npm install and npm run build inside server/.

  2. Configure the environment

    Copy .env.example to .env — your domain, where SQLite and uploads live, and (optionally, for day-to-day email sign-in) SMTP settings.

  3. Run migrations

    npm run db:migrate creates the SQLite database — nothing to provision separately.

  4. Create your owner account

    npm run bootstrap-owner — mints your account directly in the database. No working inbox required; see "How first sign-in works" below.

  5. Keep it running

    A process supervisor restarts it if it ever crashes — supervisord on Uberspace, systemd on your own VPS.

  6. Point your domain at it

    Add DNS records for your domain and api.<yourdomain>, and one more per site you create later.

How first sign-in works

Connecting the app

New self-hosted instances don't need email or SMTP configured just to get started. Running npm run bootstrap-owner interactively prints a QR code straight in your terminal, plus a short backup code if you can't scan it.

$ npm run bootstrap-owner

Scan this in the Shareblog app to connect and sign in:

Can't scan? Enter this code by hand: 7F3K-QXPZ
Expires in 20 minutes, single use.

Open Shareblog, tap Scan to Connect on the very first screen, and scan it — that sets your server address and signs you in, together, in one step. Lost it or it expired? Just run the command again.

Prefer email sign-in day to day? Set ALLOWED_SIGNUP_EMAILS in your .env to your own address and configure SMTP_* — the bootstrap step still works either way, it just means you're never blocked on email working before you can get in the first time.
